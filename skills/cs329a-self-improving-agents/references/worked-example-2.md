## What the run said about the skill

Ten things, for the next revision. None changed the verdicts; several changed how long they took.

- **The negative-search form caught a wrong verdict before it was written.** A keyword sweep for judges returned 267 hits across 69 files - `code_verifier`, `skillevaluator` - and read as "no LLM judges." Writing the DOES NOT APPLY row required the exact command, and re-running it at phrase level (`"llm judge|judge_prompt|…"`) found two judges the sweep had buried. The rule "empty output with none of those is not evidence" is what made the second search happen. Keep it; it is the skill's best line.
- **Step 7 cannot be obeyed by an agent that has to load the skill.** The references table is the first thing a fresh agent reads, and the worked example is a row in it. This run opened it before starting and says so; the next run will too. Move the answer keys into `references/answer-keys/` with their own README, so opening `references/` to learn the procedure does not open them.
- **"Bars before numbers" has a hole for numbers that arrive in prose.** The browser battery's 18/18 was in a README opened for the *inventory* - the step where reading numbers is allowed - and the bar it should have preceded was only obvious after seeing it. Disclosure handled it (count: 1), which is the designed outcome. Worth one sentence in step 3: "a number you meet while inventorying counts as read."
- **(code)/(running) is missing a third state: (installed, opt-in).** Smart approval (5a) and grounded-citations (7) both exist, both are off the default path, and neither tag says so. Their rows say it in prose; a tag would make it countable across runs.
- **UNREADABLE for a dependency outside the repo worked.** The learning loop's invariants live in a hub-installed skill. The rule "never rounded to DOES NOT APPLY" held, and listing it as an unreachable *surface* rather than forcing it into a row was the right shape - but the template's UNREADABLE line asks for ideas, not surfaces, so the count reads 0 while a real gap sits above it. Add "surfaces unreachable: N" beside it.
- **A 10k-file repo is inventoried by search, not by reading,** and the `file:line` evidence bar was satisfiable that way: every quoted line came from a grep hit and a bounded read around it. The three files over 400 KB were never opened whole and did not need to be. Say so in step 2 - a fresh agent will otherwise try to read `cli.py`.
- **The eight inventory categories mapped onto a foreign repo without a gap.** The only surface that fit none of them was "a config key nothing reads" (`eval_size`), which landed under held-out sets by content. A ninth category is not needed; a one-line note that phantom settings are evidence is.
- **Idea 2's row needs a home for single judges.** The idea is about ensembles; the repo has two lone judges with unrecorded precision. DOES NOT APPLY is correct and feels wrong. Route it explicitly: "a single judge with no label record → see 3; a single judge that is the producer → see 8," in the idea text.
- **Idea 6's bar was easy to write and hard to *not* satisfy.** Any agent framework with a 500-iteration budget is in the 50% regime; the verdict is a foregone APPLIES, and the useful content is in the failure-class inventory. Consider making 6 two halves like 5 and 9: (6a) horizon regime, (6b) failure classes counted.
- **"Time spent" should include the clone.** Fifteen of seventy minutes went to Windows path-length errors under `website/i18n/`. That is a real cost of pointing this skill at a large repo from a Windows machine, and the next reader should expect it.
