The opencode coding agent (its core, CLI, server and terminal interface) in anomalyco/opencode, read at commit 0093fe57. Claims about how the code behaves refer to that commit. Their code is MIT-licensed; this page quotes short excerpts and cites files and lines at that commit.

How to read this page

A seat is a judgment the agent makes over and over: which session a command continues, what the model sees, may this action run, is the work done. Each card records how the judgment is answered, who holds it, what checks it and what happens when it fails, and says so where something was not traced. Seat ids (A1, B12 …) are links.

The chip on each card has two words. The first is about the question: a RULE has one right answer given its inputs, so a run that answers differently is a bug; a RULING is one that competent people could answer differently. Enforcing a limit someone set is a RULE; choosing what to keep, what to trust or when the work is done is a RULING, even when code holds it.

The second word is who holds it: llm = a language-model call; model = another learned model; code = code in their repository; human = a person; external = code outside the repository that the agent hands the decision to.

Paths are relative to the repository root. A bare :120-140 means lines in the file named just before it. Whether each cited opencode issue is open or closed was checked against GitHub on 2026-10-29.

A8 When a person runs a custom command, what text is sent, under which agent and model, and in which session? RULE · code
Answered how

Code: the command's template is expanded with the person's input ($1..$n positional, the last placeholder taking the rest; $ARGUMENTS the whole input; with neither, the input is appended), then every !`cmd` left in the expanded text is run in the config-priority shell in the location directory and replaced by its output. Agent is the command's agent when set; model is the command's model, else that agent's model. A command run as a child falls back to the parent's agent, and its model to the chosen agent's model, then the parent session's model. If the command is marked subagent/subtask (or, when unmarked, its agent is a subagent) a child session is created and the text is sent there with a "You are a subagent" preface and backgrounded; otherwise the session is switched to that agent/model (when set) and the text is prompted with the caller's delivery.
