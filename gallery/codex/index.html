How to read this page

A seat is a judgment the agent makes over and over: which model runs, what the model sees, may this command run, is the work done. Each card records the question, how it is answered, and who or what holds it, with the code that implements or exposes that decision. Seat ids (A1, D12 …) are links.

Each answer describes what Codex does by default at the commit named above. Exceptions named are the main ones, not a complete list.

The chip on each card has two words. The first is about the question: a RULE has one right answer given its inputs, so a run that answers differently is a bug; a RULING is one that competent people could answer differently. Enforcing a limit someone set is a RULE; choosing what to keep, what to trust or how long to wait is a RULING, even when code holds it.

The second word is who holds it: llm = a language-model call; model = another learned model (here, image generation); code = code in their repository; human = a person; external = a service outside the repository.

Paths are relative to codex-rs/ unless they say otherwise. A bare :120-140 means lines in the file named just before it.
