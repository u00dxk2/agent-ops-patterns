How to read this page

A seat is a recurring judgment the system makes. Each card says who holds it and what checks it. The chip on each card says what kind of question it is: a RULE has one right answer given its inputs, and a run that answers differently is a bug; a RULING is one competent people could answer differently. Seat ids (A1, B12 …) are links.

The chip's first word is about the question, not about who answers it. A similarity threshold, a risk level or a "done?" check is a RULING even when fixed code holds it, because people could reasonably set it differently. The value the code happens to use is a setting (see Settings), not a separate seat. So "RULING · code" is a normal card, not a contradiction.

Some seats always give the same answer (for example, "never halt early"). They stay on the map because the question is still asked every time, and a different system, or a later version, could answer it differently. The card says the answer is constant.

Who holds it (the chip's second word): llm = a language-model call, including a hosted language-model classifier; model = a learned model that is not a language model (an embedding threshold, a classifier); code = code in this repository; human = a person; external = code outside the repository that the system hands the decision to.

Path shorthand inside cards: S/ and sdk/ = openhands-sdk/openhands/sdk/; T/ = tests/; LC = S/conversation/impl/local_conversation.py; tools/ = openhands-tools/openhands/tools/; server/ = openhands-agent-server/openhands/agent_server/. A bare :120-140 means lines in the file named just before it.

Provisional: question under a card means the wording of its question is still open; Provisional: boundary means it is still open whether the seat belongs inside this map's boundary. Not searched means nobody looked; nothing found means someone looked and the search is named.

Evidence tags. Each tag means exactly one method, and has its own colour:

  • REPRODUCED someone ran code that shows it (the method and commit are stated on the gap) (used 3×)
  • READ-LEAD the map's author re-read the cited lines at the pinned commit (used 16×)
  • READ-REVIEW a second reader (a review agent, or a reviewer from another model family) read the cited lines; the map's author did not re-read them (used 51×)
  • REPORTED OpenHands' own tracker states it (issue or PR number given) (used 0×)
  • READER-REPORTED one read-only pass reported it and nobody named has re-read it (used 2×)
  • WITHDRAWN shown for the record; not a gap (used 1×)
  • DESIGN a flag, not a method, used on gaps only: OpenHands' own code, docs or tests say the behaviour is intended (quoted on the gap); listed so a reader can judge, not claimed as a bug. A seat card that says the code intends something quotes the code instead (used 12×)

The "used" counts cover every tag on the page: the gaps carried from the first edition, the gaps found in this edition, and the DESIGN flags. They are counts of tags, not of gaps (one gap can carry two tags).

def build_classifier_prompt(meta: MetaProfile) -> str:
    """Build the classifier system prompt listing the meta-profile classes."""
    lines = [
        _CLASSIFIER_SYSTEM_PREFIX,
        "",
        "Based on the recent conversation, pick the single category that best "
        "describes the current task.",
        "",
        "Categories:",
    ]
    for i, cls in enumerate(meta.classes, start=1):
        lines.append(f"{i}. {cls.description}")
    lines.append("")
    lines.append(
        "Respond with ONLY the number of the best matching category. "
        "If none of the categories clearly apply, respond with 0."
    )
    return "\n".join(lines)
